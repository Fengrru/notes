昨天我用付费 AI 跑了个任务，一次就过——代码干净，逻辑严密，模块之间严丝合缝。我盯着屏幕愣了很久，然后突然反应过来：差不多半年前，用免费模型做同样体量的活，我得耗掉一整个下午，把能试的 prompt 技巧全试一遍，最后还被一个凭空捏造、根本不存在的 API 摆了一道。

那一刻我终于明白——**不是模型突然变聪明了，是我变强了。**

而让我变强的，恰恰是一连串当时让我恨不得把电脑砸了的事。

---

## 我丢了电脑，被 GitHub 封了号，眼睁睁看着两年的代码蒸发

事情要从去年秋天说起。

我在学校附近租了个小房间，下课后就窝在里面写代码，一直写到晚上。有天中午，我出门前先给 AI 挂了个任务——那种跑起来挺久的数据处理活——笔记本就那么摊在床上，屏幕亮着，风扇嗡嗡转。我当时想，没事，自己房间里能有什么事。

下午回来，门锁得好好的，没有任何被撬的痕迹。我脱了鞋，放下包，走到床边。笔记本没了。

我在那儿站了整整三十秒，脑子一片空白。我还翻了翻包、掀了掀枕头，想着也许是我自己拿出来了——但我心里清楚没有。出门前我还看了一眼进度条。

房东调了走廊的监控。画面里是一个人——空着手进来，拎着一个鼓鼓的包出去。我报了警，没有任何下文。

那台机器里存着我从高一起写过的每一行代码：乱七八糟的作业、一时兴起的小项目、做了一半的竞赛代码——全在本地硬盘上。我往 GitHub 上推过一些，但只在我记得的时候，而我不太记得。大部分东西从来没上过云。

然后，不到两周，我的 GitHub 账号被封了。没有任何预警。官方说法是“可疑活动”。我点了申诉链接，收到的自动回复说结果不可更改。到现在我也不知道是什么触发的——也许是校园网共享 IP，也许是某个仓库被误判。

本地备份？没了。云端副本？没了。一扫而空，清零。

那段时间我整个人是麻的。不生气，也不难过——就是空。像是我两年的存在被人擦掉了，而我拿不出任何证据证明我写过那些东西。

但大概一个月后，我翻到了当时交作业前拍的一些旧截图。看着那些代码，我后背一层冷汗——变量名叫 `a1`、`a2`、`b1`；一个函数横跨几百行，一句注释都没有；到处是空的 `try-catch` 块；数据库连接直接硬编码在业务逻辑里——想改个表结构？基本等于重写半个系统。

如果那些代码今天还在我硬盘里，我大概会抱着它们当宝贝。但把它们弄丢、把 GitHub 备份弄丢这件事，逼我承认了一件事：**那些项目唯一的价值就是练手。**代码本身没有任何长期意义。现在让我去维护其中任何一个，我宁愿用 AI 从头重写一遍——最多半天，比原来干净十倍。

从那天起，我对代码的心态完全变了。它不再值得囤积，只是你脑子里那些东西的一个临时的外化形式。**偷不走、也封不掉的，是你理解问题的能力、拆解问题的框架、分辨好坏的眼力。**这些东西会长在你身上。

## 破电脑教会我的：想清楚再敲键盘

丢了笔记本之后，我一时买不起新的，只能蹭学校的公共机房——开机要三分钟，一打开 VSCode 就轰鸣得像喷气式发动机。后来室友把他淘汰的旧机器借给了我：i5 六代、8GB 内存、机械硬盘。跑任何正经的开发环境都是折磨——Docker 想都别想，`npm install` 一装能装到宇宙热寂。

但那台破机器有个意想不到的副作用：**你会戒掉瞎折腾。**每编译一次要等很久，跑一次又要等一轮；逻辑一错，一整个下午就没了。所以你必须在脑子里把整个流程先走一遍——想清楚边界情况，把数据的走向捋顺——然后才敢敲下第一行代码。

我画满了好几个本子的流程图，手机备忘录里塞满了分步骤的拆解。真正写代码的时间很少，大部分时间都在想。这个习惯一直留到今天，哪怕后来换了设备、开始用付费 AI 也一样。唯一的区别是现在想得更快，因为脑子里攒下了一个模式库。

**那个性能瓶颈其实是一道筛子**——它把低质量的试错挡在外面，只让真正带着思考的操作通过。当时觉得是诅咒，回头看，那段时间可能是我代码写得最扎实的时候。

## 免费模型：最差的老师，最好的教练

然后是免费模型。说实话，就是因为穷。

对学生来说，付费 AI 订阅不便宜，按 token 计费的 API 更是想都别想。于是我靠着各家平台的免费额度凑合，用的都是参数量不大、能力有限的模型。

免费模型是真不行。稍微复杂一点的问题，它就开始幻觉；让它写代码，它把 Python 和 JavaScript 的语法混在一起；让它算个平均数，它都能算错。但也正因为它们这么不靠谱，**我被迫学会了怎么把模型用好。**

有一次我需要一个 Python 脚本，把一堆 CSV 合并、去重、排序。免费模型给的第一版有个致命 bug——它直接把所有重复行全删了，而我要的是每个 key 保留第一条。我没有让它去修。我把任务拆成三步：先按 key 分组，再取每组里时间戳最早的那条，最后把结果合起来。每一步单独问，每一步的输出都手动核对，然后自己拼起来。花了两个小时，但 pandas 的 `groupby` 我记到今天——因为是我一行一行亲眼验证过的。

免费模型的上下文窗口也小。粘一大段代码进去，它就忘了你前面说过什么。于是我养成了一个习惯：**给上下文，永远越精简越好。**把废话全砍掉，无关的函数全删掉，只留最核心的部分。这逼着我去分辨一段代码里什么是必要的、什么是装饰。后来用付费模型，这个习惯我也留着——问题很短，但信息密度极高。

还有幻觉问题。免费模型撒谎面不改色，语气笃定得不得了。被坑了几次之后，我练出一种条件反射——**AI 告诉我的任何东西，尤其是数字、API 名字、配置路径，默认不信，先自己验证。**要么去翻文档，要么写个小测试跑一下。绝不无脑复制粘贴。

开始用付费 AI 之后，这个习惯的回报巨大。付费模型准得多，但也没有 100%。因为我很早就被训练成了“不信就验”的模式，我几乎没再掉进过 AI 挖的坑里。

免费模型没什么创造力，所以我没法指望它自己想出方案——方案得我自己想清楚，它们只负责执行。这教会了我**把 AI 当实习生用：**背景、目标、约束、格式，连示例都要给清楚。你给的细节越多，它的产出越好。那种“随便丢一句话等奇迹发生”的幻想，在用免费模型的第一周就被现实碾碎了。

## 一切在一个项目里汇合

所有这些经历——丢光代码之后对“什么才是有价值的工作”的重新认识、在破机器上磨出来的“想清楚再动手”、被免费模型硬生生磨出来的拆解能力和验证本能——最后都汇进了同一个项目。

这个项目叫 **Scientific Contradiction Detector**，一个自动检测研究论文中矛盾结论的学术工具。

核心问题是这样的：一个很窄的领域——比如大语言模型里的 Chain-of-Thought 数学推理——从 2021 到 2026 年大约产出 200 篇论文。没有任何一个研究者能全部读完。互相矛盾的结论发表在不同的期刊上，从来没有人把它们对照起来看。研究者在互相矛盾的地基上继续盖楼，却不知道自己脚下的地和别人不一样。

这个系统做的事：扫描 200 篇论文，抽取结构化论断，然后标出“谁在什么问题上和谁矛盾”。它最终找出 **165 处已验证的矛盾**，其中 76% 属于“实验条件不一致”——不同论文做出了同一个论断，但一篇是在 GSM8K + GPT-3.5 上测的，另一篇是在 MATH + Llama-2 上测的。表面上看一模一样，实际上根本不可比。这类系统性不一致，此前从未被人成规模地记录过。

这是一条四阶段的流水线，覆盖了从数据采集到自动生成论文的全流程：

```
200 papers (arXiv + Semantic Scholar)
  → PDF text extraction (PyMuPDF)
  → Structured claim extraction (DeepSeek API / Llama 3 8B 4-bit quantized)
  → 6-tuple format: Subject | Relation | Object | Condition | Evidence Type | Confidence
  → Data cleaning (ontology normalization + synonym mapping)
  → Candidate contradiction generation (same SRO + opposite relation)
  → Rule engine (4 patterns) + LLM fallback classification
  → Significance scoring (0.6 × log citations + 0.4 × confidence)
  → Streamlit interactive interface + automatic LaTeX paper generation
```

技术栈：Python 3.10+、PyTorch、Transformers、Llama 3 8B Instruct（4-bit 量化）、DeepSeek API、Streamlit、Plotly、PyMuPDF、NetworkX、pandas、scikit-learn。大约 20 个源文件，横跨数据、抽取、检测、输出四个架构层。

规则引擎是最“我”的模块——四条硬编码的默认规则（相反关系、数据集冲突、模型对比、统计偏差）处理确定性模式，**零幻觉**；一个 `_find_common_patterns()` 函数从人工验证过的矛盾里自动挖掘新模式，推导出新的检测规则。这基本上是“先把逻辑想透，再让 AI 写代码”的究极形态——规则由人定义，AI 只负责把逻辑翻译成 Python。

Streamlit 前端有四个标签页：统计面板、矛盾浏览器、论文网络图，以及 Paper Analyzer（支持上传 PDF 或粘贴文本，LLM 与关键词双模式抽取，并与已有数据库实时比对）。

## 那这个项目到底是怎么做出来的？

这才是我真正想讲的部分。

**这个项目的代码，是在 Windsurf 平台上、用免费模型 SWE-1.5、在一次对话里、一遍写完的。**

但在打开 Windsurf 之前，我先打开了 Kimi。

我在 Kimi 里写完了整份设计文档——领域定义、数据流、模块拆解、API 设计、错误处理策略、配置文件结构，甚至连 Streamlit 四个标签页各放什么。我写完，改了好几遍，确认没有逻辑漏洞，然后把这份文档当成 prompt 粘进 Windsurf，让 SWE-1.5 开始写代码。

所以严格来说，Kimi 是我“想”的地方，Windsurf 是我“做”的地方。Kimi 负责把我脑子里的架构变成一份结构化规格；SWE-1.5 负责把规格变成能跑的 Python。

没有来回修改，没有“推倒重来”。一个对话窗口，从项目初始化到最后一个 Streamlit 页面渲染出来——全部完成。

这听起来像在炫耀，但如果你把上面这些经历都读完了，你应该已经明白了——这不是模型有多厉害。是那些苦日子把我的“输入”磨到了完全另一个层级。而 Kimi 这一步“想”，本质上就是这半年训练出的习惯的延伸：**在让 AI 干活之前，先用另一个 AI 把需求写到滴水不漏。**

在打开 Windsurf 那个对话窗口之前，完整的图景就已经在我脑子里，也在 Kimi 的文档里了：

- 选哪个领域？（CoT 数学推理——概念可形式化，150-500 篇论文的规模管得过来）
- 数据怎么流动？（arXiv 抓取 → PDF 下载 → 文本抽取 → 论断抽取 → 矛盾检测 → 结果输出）
- 每个模块的输入输出是什么？（paper_fetcher 输出 CSV → pdf_downloader 输出 PDF → text_extractor 输出带文本的 CSV → claim_extractor 输出六元组 → contradiction_detector 输出矛盾对）
- 规则引擎怎么设计？（先把 4 条确定性规则硬编码，给自动推导留一个接口）
- Streamlit 四个标签页各放什么？（Overview、Browse、Network Graph、Analyzer）
- 配置文件什么结构？（YAML，用 ${ENV_VAR} 模式解析，方便部署）
- 连错误处理都想好了？（重试逻辑、mock 模式、备份频率）

这些都不是 AI 帮我想的。AI 帮不了我想。一个连 API 都能凭空编出来的免费模型，我怎么可能指望它设计出一套真能跑的架构？

**AI 做的全部事情就是：把我已经想清楚的逻辑翻译成代码。**我说“需要一个 RuleEngine 类，4 条默认规则，每条规则是一个 condition_func 闭包，analyze_pair 方法返回 (type, confidence, matched_rules_list)”——它就写出来了。我说“需要一个 `_find_common_patterns` 方法，从验证过的数据里统计 subject-relation-object 共现模式，按阈值生成新的 condition_func”——它也写出来了。

它写出的每一行代码，在让它写之前，我大致都知道会长什么样。

这就是在免费模型身上练了半年的肌肉记忆：**打开对话窗口之前，先把问题拆清楚。**因为我太清楚免费模型的毛病了——边界不钉死，它就开始自由发挥，而自由发挥意味着一整个下午打水漂。

## 不是模型变聪明了，是你的脑子变了

回头看这半年，我想说的话其实很简单：

**限制本身不是坏事——取决于你怎么用它。**

如果笔记本没被偷，我大概还抱着那些垃圾代码当宝贝。如果 GitHub 没封我，我也许永远不会问自己“如果从头重建，我能不能做得更好”。没有在破电脑上熬的那段时间，我可能还是“先堆一堆代码，出了问题再调”的那种人。没有被免费模型折磨几个月，我永远不会明白什么叫真正的写 prompt。

AI 很强，但它是被动的。输入的质量决定输出的质量。学过手动挡的人开自动挡轻而易举；只会开自动挡的人，一坐进手动挡的车就会熄火。我就是那个开了半年手动挡的人。

我现在效率高，原因不在模型——模型只是帮我省了打字的时间。真正让我高效的是这几个月建起来的工作流：**需求拆解 → 架构设计 → 信息组织 → 交叉验证 → 永远不让 AI 替你思考。**这些东西现在就是你的一部分。不管你换什么工具，它们都在。

所以，如果你现在正只能用着免费模型、守着一台破电脑，还因为丢了代码而难受——**你可能正处在学习曲线里最值钱的一段。**这一段不会给你便利，但它会给你重要得多的东西：在约束下找解法的经验、在匮乏里调配资源的能力、以及工具失灵时自己顶上的底气。这些能力一旦长在你身上，谁也拿不走。

而当你终于用上更好的工具那天，你会发现——你踩过的每一个坑、每一次被幻觉 AI 气到想砸键盘、每一个因为电脑太慢被迫在脑子里把问题多翻三遍的下午——全都不是白费的。

至少对我来说，都没有白费。
